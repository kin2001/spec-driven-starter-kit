# Inline executor with independent review

For a newly started coherent delivery, default to **inline execution**: the existing main session retains Relay's controller responsibility, performs Forge/Pixel implementation itself, and later performs Dock's authorized integration checklist. Lens remains a separate independent reviewer and, when selected, acceptance evaluator. Roles describe responsibilities, not mandatory concurrent sessions or model changes. This removes routine parent/implementer and parent/Dock supervision; it does not eliminate CI/review waits.

## Choose and record the mode once

After current ownership, approved package, target issue and relevant environment checks, fill the existing dispatch as an assignment record even when no worker is spawned. Record **Execution mode** (`inline`, or `delegated exception` with reason/ownership), **Actual main model** and effort (observed or unknown), main session/worktree/snapshot, implementation scope, independent Lens setting and required checks. Put the same mode/model observations in the existing report. Do not add a run schema field, new agent or parallel tracker.

An inline main uses its actual configured host model for the entire issue. It is not required to impersonate the Forge/Pixel/Dock profile or secretly switch model/effort. A parent Sol Medium remains Sol Medium when implementing UI or integrating. Standalone role profiles retain their explicit settings for actual dispatch; Lens still requires its supported requested model/effort and observed evidence under the runtime contract. An explicit owner requirement for a particular executor setting must be honored or reported unavailable, not silently substituted. Profile names never prove routing or a sandbox. No global settings changed by this mode.

Retain a live delegated issue's current mode until its coherent work and ownership are reconciled at a safe boundary. Do not interrupt workers or rewrite their responsibilities to adopt this default. Apply at the next issue boundary; preserve historical dispatches/model evidence. Starting a fresh chat still requires normal authorized ownership transfer. For existing installations, reconcile only backed-up workflow files at the controller-approved quiet window and put next-task mode/limitations in HANDOFF.md.

## Execution sequence

1. Main acts as Relay for current authorization, single claim, Linear and run state. Read the compact handoff, current target once and relevant source sections, not the entire roster's instructions. Use the existing worktree/isolation/overlay process. Main explicitly owns product/shared-resource writes; no separately dispatched implementer watches or duplicates it.
2. Main performs the approved Forge/Pixel work and environment preparation directly using `$executing-plans`, relevant TDD/debug/UI guidance and existing patterns. Do not invoke a subagent-per-task execution skill for an inline assignment. Scope and acceptance remain those approved; preparation follows the same recipe/service/secret boundaries. Store logs locally and return concise results. Reuse valid known-baseline evidence only while relevant inputs match; required final checks still run.
3. At one coherent review-ready candidate, request a fresh independent Lens with relevant issue/contracts/current diff and exact repository/head/base/tree. Lens does not fix code, write Linear, integrate, or grade the main's self-review as independent evidence. If no independent reviewer can be dispatched, record the capability gap and withhold dependent readiness/integration. Do not manufacture PASS or quietly remove the gate.
4. Main owns CI observation by default; Lens consumes its saved result plus source evidence and independently judges it. Lens may execute distinct focused checks needed for its judgment, but should not duplicate polling of the same running CI. Honor host wait/communication rules, preserve user interruption and required result collection. Never end the main turn and assume an idle worker message will restart it; native dispatch/end-turn auto-wake was not demonstrated in the pilot. A hung Lens triggers bounded liveness/reconciliation, not a replacement writing alongside it.
5. Main fixes findings as implementer, preserving failures and uncertain operations. Changed code/base/tree requires affected rechecks and independent re-review; previous verdicts remain historical. Lens code review and owner-selected manual or Lens automated acceptance remain separate and bound to the same final snapshot. No self-acceptance under a different role name. Selected human/environment gates stay pending until evidenced.
6. Only after matching independent review, selected acceptance, final required CI, current ownership/stop state and enforceable provider protections, main performs the Dock checklist using runtime.md and tested operations helpers. Check actual current head/base/protection and expected-head integration; reconcile unknown merge before retry. Verify merge/tree and retain required ignored evidence before native cleanup. A helper byte receipt or main's confidence never authorizes deletion or bypass.
7. Main, still sole Relay writer, updates/readbacks Linear and saves verified run/report/handoff. Preserve model observations, unresolved carryover and trial metrics. No new issue or review for each small edit. A later context refresh follows the same safe checkpoint/transfer contract; no arbitrary token timer.

## Delegated exceptions

Use a separately dispatched implementer or Dock only when justified by a concrete need: independent parallel work with non-overlapping files/resources, an explicit host/model/permission requirement, or a bounded specialist task that cannot reasonably remain inline. Record the reason and actual owner/inputs/return condition before dispatch, with appropriate worktree and shared-resource isolation. Do not trigger an exception solely because the roster contains a role or an issue has several checklist steps. Apply existing fresh-worker/quiet-coordination contracts to real dispatches. Independent Lens is required, not an exception.

## Failure and rollback

| Situation | Required behavior |
| --- | --- |
| Main code and independent result disagree | Preserve both evidence sources; resolve findings and re-review, no self-PASS. |
| Main model differs from a role profile | Record actual parent setting; profiles govern actual dispatch. Honor explicit owner setting requirements. |
| Main crashes or quota expires | Retain WIP/checkpoint and unknown operations; reconcile before authorized resume, no automatic takeover. |
| New code after Lens PASS | Refresh affected checks and Lens evidence before integration. |
| Review/CI wait still wakes main | Report remaining host overhead; do not promise zero waiting or drop review. |
| Parallel work becomes necessary | Record delegated exception and isolated ownership before writes; never two writers in one checkout. |
| Trial rollback | Quiet affected workers, restore only unchanged applied workflow/profile hashes from backups; preserve approvals/run/claim/product WIP and current evidence. Resume original mode only after reconciliation. |

Measure overall main+reviewer effort, context, coordination calls, correction rounds, cleanup errors and retained quality gates on a coherent task. Fewer agents need not guarantee lower allowance: an inline parent may be a different model from a delegated implementer. Keep defaults stable for the pilot, record actuals, and compare similar deliveries. No external scheduler or auto-resume integration is installed.
